# ADR-0014: The token registry is the list of what exists

**Status:** Accepted · 2026-09-10

## Context

The doctrine says a component never skips a layer and never invents a value
(`docs/css-doctrine.md` §2, ADR-0008). Nothing told an author what the
layers contain. The tokens are authored in JS and delivered as six generated
CSS files (ADR-0003) holding about 1 500 declarations, most of them four-mode
and four-tier duplicates of a few hundred names. An author, human or model,
who wants "the border colour" either reads all six files or guesses. The
cleanup pass found the guesses: raw `oklch()` shadows in Card, hex fallbacks
in Notice, `0.5rem` where `--ui-radius` existed.

A rule that cannot be checked at the moment of writing is a preference. The
missing piece is not enforcement — Nicklas declined a test that greps
components for RAW names — but a list short enough to read whole.

## Decision

1. **The generator emits a registry**, `docs/tokens.generated.md`, built by
   `engine/registry.js` from the same factories that emit the CSS. It lists
   every custom property a component may reference, per layer, in
   resolution-chain order, with a one-line role. **Names and roles only,
   never values**: values switch by appearance and tier and resolve at
   runtime; a value on the page would be read as a constant.
2. **The registry is the definition of "exists".** A name not on the page
   does not exist. An author who needs one writes a `TODO(token)` beside
   the raw value and raises it as a finding; nobody invents a token or a
   value in a component.
3. **Layer visibility is stated on the page** (ADR-0004): component slots
   are private (ADR-0013); theme channels are read with one fallback
   (ADR-0008); semantic tokens are read directly; the `--ui-*` seam is the
   reference-components surface (ADR-0002); RAW constants are for the
   semantic factories only.
4. **Roles are authored where the token is authored.** A `/** … */` doc
   comment above a token key in `theme-default/*.tokens.js` is its role in
   the registry. The test that keeps the registry fresh also fails when a
   semantic colour token has no role.
5. **The registry is a generated artifact** like the CSS: never hand-edited
   (the PreToolUse hook covers `*.generated.md`), regenerated by
   `pnpm tokens`, freshness guarded by `tests/tokens.test.ts`.
6. **The doctrine and the repo guide point at it.** `css-doctrine.md` §2
   names it as the list to choose from; the root `CLAUDE.md` reading table
   says when to read it: before writing any `var()` in a component.

## Alternatives rejected

- **A hand-written token guide.** Rejected: it would be stale by the second
  token change, and the CSS is already generated from a single source.
- **A test forbidding RAW names in components.** Declined by Nicklas
  ("we can live without a hard rule"). The registry makes the rule legible;
  legibility is the bet.
- **Values on the page.** Rejected: a light-mode hex beside a token name
  invites copying the hex.

## Consequences

- `pnpm tokens` writes seven artifacts. The registry is committed like the
  CSS and reviewed in the same diff as the token change that moved it.
- Every semantic colour token now carries a role; the other layers use
  their section descriptions. Roles for `--size-*`, `--grid-*` and the
  typography bundles can be authored later in the same way.
- The `--SITE--PADDING` alias in the seam (a reference-components name)
  appears on the page under the seam; it is the one uppercase name a
  component may read, and it is a port artefact to retire.
- ADR-0004, which the registry's layer rules rest on, was translated to
  English in the same branch (hard rule 1).
